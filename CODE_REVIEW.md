## P0 — потеря данных

### 1. Одиночное удаление сообщения в чат-редакторе удаляет ДВА сообщения
`src/features/feature-chatedit-engine.js:359-364`

Путь `change.action === 'delete'` для одиночного `msg_index` делает и `msgs.splice(idx, 1)`, и `ctx.deleteMessage(idx)`. Ядро SillyTavern внутри `deleteMessage(id)` само делает `chat.splice(messageId, 1)` над тем же живым массивом `ctx.chat` (и удаляет DOM-узел — guard раннего выхода не срабатывает, т.к. расширение DOM не трогало). Итог: вместе с целевым сообщением вырезается следующее, и `_persistChat` пишет оба удаления на диск. Путь `msg_indices` (строка ~324) корректен — только splice.

**Фикс:** убрать `msgs.splice(idx, 1)` и оставить только `ctx.deleteMessage(idx)` (или наоборот — только splice + `_saveChatAfterDelete`, как в `msg_indices`-ветке).

## P1 — видимые поломки

### 2. Tool-раунды дублируют историю предыдущих раундов в контексте
`src/api.js:1300-1302, 1319-1321` · подтверждено вручную по коду

> **ОТЗЫВ 2026-10-28:** находка опровергнута живой проверкой (перехват тел запросов при реальной tool-генерации с 2 раундами): запросы содержали 4 → 6 → 8 сообщений без дублей — фильтр `session.messages.filter(m => !m._tcTemp)` (`api.js:1370`) вычищает temp-сообщения в конце каждого раунда, и повторный пуш стартует с чистого массива. Ошибка ревью: агент не заметил фильтр.

`nativeHistory` / `extraHistory` накапливаются между раундами (объявлены вне цикла, `api.js:1163-1164`), но пуш-цикл внутри `for (round...)` каждый раз прогоняет **весь** массив. Раунд 0 пушит 2 temp-сообщения, раунд 1 — те же 2 + свои, раунд 2 — все 6: дублирование O(rounds²). `tempSession` (`api.js:1334`) фильтрует только `streamMsgId`, не `_tcTemp`, поэтому следующий `callGenerate` отправляет контекст с повторяющимися парами assistant/tool и дублями `tool_call_id`. Строгие провайдеры (Anthropic — ошибка на повторный `tool_use_id`; многие OpenAI-совместимые шлюзы — 400) отклоняют запрос. Воспроизводится детерминированно при 3+ tool-раундах в обоих протоколах.

**Фикс:** пушить в `session.messages` только дельту раунда (срез новых элементов), либо чистить `_tcTemp` перед пушем следующего раунда.

### 3. Транспортная ошибка чтения bucket-файла считается «повреждением» — сессии осиротевают
`src/session.js:356-361, 476-490`

`loadSessionFile` при `!res.ok` бросает `HTTP ${status}`, catch возвращает `false` — то же значение, что и для непарсящегося payload. `initChatBucket` уходит в recovery-ветку: переписывает `chatMetadata.st_copilot` на новый пустой файл и показывает «файл повреждён». Один 500/502/сетевой сбой на `GET /user/files/...` навсегда переключает чат на пустое хранилище (в этом пути даже `.corrupt`-бэкапа нет — он только для parse-failure).

**Фикс:** различать транспортный сбой (`null`) и реальную порчу (`false`); recovery — только на порчу.

### 4. `EXT_DISPLAY` не импортирован в ui-chat.js — guard'ы свайп-кнопок падают с ReferenceError
`src/ui/ui-chat.js:682, 706, 744`

Три обработчика prev/next/delete свайпов ссылаются на `EXT_DISPLAY`, которого нет в импортах файла (и нет на `window`). При клике по свайп-кнопке во время редактирования сообщения вместо тоста «Сначала завершите редактирование» — unhandled ReferenceError без какого-либо фидбека. Навигация блокируется случайно (самим броском).

**Фикс:** добавить `EXT_DISPLAY` в импорт-блок `ui-chat.js`.

### 5. Edits authors_note / user_persona / evolutia-полей не инвалидируют кэш системного промпта
`src/features/feature-character-engine.js:527-557, 593-633, 635-645`

Эти ветки `saveCharacterField` завершаются `ctx.saveSettingsDebounced()` / `ctx.saveMetadata()` — в обход обёртки `saveSettings()` (`src/session.js:150`), которая вызывает `invalidateSystemPromptCache`. Подпись кэша (`api.js:151`) не покрывает `chatMetadata.note_prompt` и персону. После правки authors-note или персоны (моделью или менеджером персонажей) последующие генерации переиспользуют устаревший `<authors_note>` / `<{{user}}_persona>` до случайной посторонней инвалидации. Тот же класс бага, что исправлен для createSession.

**Фикс:** инвалитировать кэш в этих ветках (или перевести их на extension-обёртку `saveSettings`).

### 6. Zombie-генерация после смены чата делает новые платные запросы
`src/ui/ui-chat.js:2167-2170` (CHAT_CHANGED, проводка `index.js:589`)

`onChatChanged` делает `abortController.abort(); state.generating = false;`, но **не** ставит `state.generationStopped = true`. Если аборт попадает в окно исполнения tool-раундов, guard'ы `api.js:1272` и `api.js:1236` оба ложны (контроллер уже занулён) — зомби запускает следующий `callGenerate` с новым AbortController: реальные запросы к API вплоть до `toolsMaxRounds`. Результат потом пишется через `saveSessionsToMetadata()` уже в bucket нового чата (тихо теряется).

**Фикс:** в `onChatChanged` ставить `state.generationStopped = true` перед/после abort.

### 7. `characterId` (индекс массива) как ключ персистентности памятей и статистики
`src/session.js:161-185` + `src/features/feature-memory.js:31-33`, `feature-stats.js:48-51`

`getBindingKey()` возвращает `String(ctx.characterId)` — volatile-индекс в ростере. Удаление/перестановка персонажей сдвигает индексы: character-scoped память (и chat-scoped, тоже содержащая charId) молча цепляется к другому персонажу и инжектится в его промпт как «факт». Статистика мисаттрибуцируется так же. Остальное расширение идентифицирует персонажа по стабильному `char.avatar` — здесь единственное расхождение.

**Фикс:** ключ по `avatar` (или другому стабильному id) вместо индекса.

## P2 — деградация и несинхронизированные пути

8. **Edit/delete сообщения без guard'а `state.generating`** — `ui-chat.js:1183, 1397`. Правка стримящегося сообщения перезаписывается финалом генерации; save-and-send во время генерации делает `truncateAfter`, а `runGenerate` но-опится — реплики обрезаны без регенерации.
9. **Чат-пикер не закрывается при смене чата** — `ui-chat.js:2166-2199`. Открытый оверлей показывает строки старого чата; Apply персистит чужие `pickedChatIndices` в сессию нового чата → загрязнение контекста. Тот же класс «забытой инвалидации».
10. **`restoreMessageDOM` теряет tool-карточки** у сообщений без persisted `toolCalls` (нет fallback `parseToolCallsFromText`, в отличие от `_renderMsgBodyContent:538`) и не прогоняет `postProcessHTMLBlocks` для отредактированного reasoning — `ui-chat.js:1254-1299`.
11. **Конкурентные `applyLBChanges` теряют правки** — `feature-lorebook-ui.js:204-209, 640-658, 825-847`. Каждый вызов клонирует базу книги и сохраняет целиком с `overwrite: true`; параллельные вызовы по одной книге — last-write-wins, карточка при этом показывает «applied».
12. **Изменения embedded-книги персонажа репортятся как применённые, но не сохраняются** — `saveWorldInfoBook` для `_embedded` делает no-op с warning-тостом без throw (`feature-lorebook-engine.js:135`); apply-цикл считает изменение успешным, блок вырезается, история пишет ACCEPTED.
13. **`ask_user` может подвесить генерацию навсегда** — `feature-tools-ui.js:162-206` + `api.js:1248`. Promise резолвится только сабмитом пользователя; не обёрнут в `withTimeout`, не привязан к abort/Stop. Смена сессии уничтожает инпут — `state.generating` залипает навсегда.
14. **Индексы не ремапятся между изменениями одного батча чат-редактора** — `feature-chatedit-engine.js:245-350`. `[delete #5, overwrite #10]` перезапишет изначальное #11 (валидация индексов шла по снимку до мутаций; descending-сортировка защищает только внутри одного delete).
15. **Failed char-правки помечаются applied и вырезаются из пропозала** — `feature-character-ui.js:190-193, 602-609, 770-772` (в отличие от lorebook/chat UI, где applied сверяется с pending).
16. **Пакет проблем персистентности сессий** (все `src/session.js`):
    - Flush отложенных сейвов в `initChatBucket:414-427` fire-and-forget и гонит с последующей загрузкой того же файла (A→B→A быстрее 1с — queued-правки теряются).
    - Удаление последней сессии не персистится: `bucketHasContent`-guard (`:236-239`) пропускает запись пустого bucket, на диске остаются старые сессии — «воскресают» после перезагрузки.
    - `beforeunload`-flush (`:304-316`) не работает для реальных размеров: keepalive-fetch ограничен 64 KiB телом, base64 bucket'а больше — тихий отказ.
    - Провал дебаунс-сейва (`:532-541`) не ретраится и не показывается: запись удаляется из очереди до записи, сбой = потерянный payload.

## P3 — мелочи

17. `extractToolCallPlaceholders` (`ui-chat.js:375, 385`) даёт пустому фенсу 1 слот → сдвиг tool-карточек при плоском ре-парсинге.
18. «Показать ещё…» во время поиска сбрасывает поисковые хайлайты (`ui-chat.js:1424-1428, 1458-1462`).
19. Stream-renderer: shrink-only диффинг не ловит rewrite с сохранением длины (`stream-renderer.js:178-192`); курсор остаётся до свежезакоммиченного блока при пустом pendingTail (`:155`).
20. Мобильная детекция в `ui-window.js` вычисляется один раз — после ротации/ресайза теряются ручки ресайза или ломается fullscreen-режим.
21. `_runSwipeRegen` (`ui-chat.js:842-848, 957-959`): не сбрасывает `generationStopped`; токен-оценка `[object Object]` для мультимодального контента (+ отравленный кэш токенов).
22. Кэш системного промпта живёт между ходами «случайно»: `recordStat` мутирует `settings.stats` → сигнатура всегда меняется → «полезный» miss каждый ход. Реальные дыры сигнатуры (live `ctx.chat` для keyword-scan лорбука, `chatCompletionSettings.system_prompt`, persona, имена участников группы) сейчас маскируются этим churn'ом — трогать надо одним коммитом с полным покрытием входов.
23. `integ-regex.js:5-12`: неудачный разовый импорт regex-движка залипает на всю сессию страницы.
24. `integ-summaryception.js:17`: `template.replace('{{summary}}', summaryText)` интерпретирует `$`-паттерны в тексте сводки — нужен function-replacer (как в `expandOutletsAsync`).
25. `init()` в `index.js:505-519`: `_initDone` защёлкивается до await'ов, try/catch нет — один сбой инита навсегда отключает расширение до перезагрузки страницы.
26. `feature-stats.js:43-52`: бакеты статистики растут вечно (день-ключи не подрезаются), весь `settings.stats` ре-стрингифицируется в каждой подписи промпта.
27. `feature-memory.js:158-166`: повторный `add` с тем же scope+key аппендит значение (`mem.value + '\n' + ...`) без предела — память распухает в каждом промпте.
28. `deleteEntryDetail` (`feature-lorebook-ui.js:1201-1215`) без guard'а embedded-книги (у `saveEntryDetail`/`addNewEntry` guard есть).

## Рекомендованный порядок работ

1. **P0 №1** (двойное удаление) — немедленно, это тихая потеря данных пользователя.

Фикс: `genEpoch++` в `onChatChanged` + проверки `myEpoch` в round-loop и execEntry (`8b9ef91`).

- ✅ **[P2] visibilitychange-флаш удалял записи очереди — beforeunload keepalive оставался без работы** (`session-storage.js`). Фикс: записи сохраняются (таймеры гасятся), keepalive переотправляет (`8b9ef91`).
- ✅ **[P2] Catch-путь генерации оставлял пустой стрим-плейсхолдер** → `content:''` утекал в bucket. Фикс: удаление пустого плейсхолдера в catch (`8b9ef91`).
- ⬜ [P3] Двойной Send с вложениями: второй съедается молча после очистки input (guard без восстановления input).
- ⬜ [P3] Классификация ошибок генерации по shared-глобалам вместо epoch.
- ⬜ [P3] ask_user после Stop: DOM-инпут остаётся с мёртвым резолвером.
- ⬜ [P3] Ретрай неудачного сейва может откатить данные после пере-входа в чат (stale payload).

## Перфоманс и память

- ⬜ **[P1] Каждый сейв сериализует весь bucket + двойной base64 синхронно на main thread** (`session-storage.js:54`); вложения-датаURL живут в messages и пере-сериализуются каждый раз. 10МБ bucket → ~30МБ строк + ~50-300мс блокировки, несколько раз за ход.
- ⬜ **[P1] Лорбук keyword-scan: toLowerCase всего текста на каждую запись ×2** (`feature-lorebook-engine.js:226`); 1000 записей → ~2000 полных сканов ≈ 100-300мс за ход. Фикс тривиален (lowercase один раз + кэш компиляции regex).
- ⬜ [P2] assembleMessages собирается дважды за генерацию (+ каждый tool-раунд); токен-путь джойнит весь промпт.
- ⬜ [P2] При появлении tool-фенса — полный ре-парс текста на каждый RAF-чанк (O(N²) агрегатно).
- ⬜ [P2] renderSession: ~30 полных проходов на сообщение (getDisplayContent дважды), ~100-300мс хич на смене сессии.
- ⬜ [P3] Стрим-рендер: prefix-slice+сравнение O(renderedLen) на чанк (minor-GC шум).
- ⬜ [P3] Свайпы+reasoning хранят 2-3x дубли текста; не пуржатся.
- ⬜ [P3] Не-quiet saveSettings (звезда, слайдер) инвалидирует промпт-кэш и форсирует перестройку лорбука.
- Чисто: стрим-рендерер инкрементален и ограничен; ленивое окно; кэши с капами; старт лёгкий; слушатели не текут.

### Постскриптум: багрепорт из поля (2026-10-29, до фикса рефакторинга)
