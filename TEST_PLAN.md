# Test Plan — ST-Copilot

Стратегия тестирования: 4 трека от дешёвых детерминированных к дорогим живым.
Базовая линия: `npm run check` (vitest + сборка + проверка свежести бандла) перед каждым коммитом.

## Трек A — детерминированные тесты (vitest) ✅ в репо

## Трек B — синтетический LLM-бэкенд (живая таверна) ✅ харнесс в репо

`tests/live/synthetic-llm.js` — вставляется в контекст страницы (браузерная автоматизация);
патчит `window.fetch` на generate-эндпоинте и скриптует поведение «модели» без реального API.

Сценарии и статус (прогон 2026-10-28):
- ✅ **pathological-stream**: незакрытый фенс + memory-блок + 50К символов одной строкой + tool-фенс — гигант сохранён, memory вычищен, tool-cut + раунд 2 дописал «финал»
- ✅ **tool-rounds-5**: ровно 6 запросов на 5 раундов, финальный текст в DOM, 5 карточек инструментов
- ⬜ **mid-stream-drop**: обрыв соединения после N чанков (харнесс готов, прогон вручную)
- ⬜ **stall**: сервер молчит → stall-watchdog (3 мин реального времени, прогон вручную)

## Трек C — соук на живой таверне (по запросу, вручную)

1. Большой чат (1000 сообщений через `/api/chats/save`) → поиск/пикер/loadOlder, замеры `performance.memory`.
2. Две вкладки на один чат → документировать clobbering bucket-файла (last-write-wins).
3. Соук 10–15 минут: цикл генераций/свитчей/правок с наблюдением DOM-узлов, памяти, ошибок консоли.

## Ограничения

- IAB-браузер не поддерживает file upload — сценарии вложений только на юнит-уровне.
- Реальная модель в цепочке только для смоука; всё повторяемое — через синтетический бэкенд.
- Пуш в GitHub не выполняется (local-only): CI заменяет `npm run check` локально.
